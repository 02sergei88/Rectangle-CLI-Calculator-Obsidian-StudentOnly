
## Требования к представлению проекта при защите

Для допуска проекта к защите студент **обязан предоставить** следующий комплект материалов.

---

### 1. Git-репозиторий проекта

Студент должен предоставить ссылку на Git-репозиторий (GitHub / GitLab / Gitea и т.п.), содержащий **полную историю разработки проекта**.

Требования:

1. Репозиторий должен быть **публичным** или предоставлен преподавателю с доступом.
    
2. История коммитов должна быть:
    
    - **равномерной во времени** (разработка в несколько этапов),
        
    - не допускается ситуация, когда весь проект добавлен **одним коммитом или в один день**.
        
3. В истории должны прослеживаться логические этапы разработки, например:
    
    - создание каркаса проекта;
        
    - добавление модели вычислений;
        
    - реализация CLI-версии;
        
    - добавление GUI;
        
    - доработка интерфейса, валидации, упаковки.
        
4. Коммиты должны иметь **осмысленные сообщения** (не допускаются сообщения вида `update`, `fix`, `123`).
    

> ❗ Репозиторий, созданный «задним числом» или с историей из 1–2 коммитов, считается **несоответствующим требованиям**.

---

### 2. JAR-архив приложения

Студент должен предоставить **JAR-архив** приложения.

Требования:

1. JAR-архив должен:
    
    - корректно запускаться;
        
    - содержать GUI-версию приложения (JavaFX).
        
2. Запуск должен быть возможен:
    
    - либо командой `java -jar <имя>.jar`  
        (при наличии сопроводительного скрипта, если требуется JavaFX),
        
    - либо с использованием предоставленного `run.cmd` / `run.sh`.
        
3. В репозитории должна присутствовать инструкция по запуску JAR-файла (в `README.md`).
    

---

### 3. EXE-версия приложения (без JVM / JRE)

Студент должен предоставить **исполняемую версию приложения**, запускаемую **на целевой операционной системе без установленной JVM или JRE**.

Допускаются следующие варианты:

1. **Установщик** (MSI / EXE), созданный с использованием `jpackage`;
    
2. **App-image / папка приложения**, содержащая:
    
    - встроенную Java Runtime;
        
    - JavaFX;
        
    - исполняемый файл приложения.
        

Требования:

- приложение должно запускаться **двойным кликом**;
    
- наличие установленной Java на машине пользователя **не требуется**;
    
- иконка приложения должна быть задана;
    
- приложение должно корректно открывать графический интерфейс.
    

---

### 4. README.md (обязательно)

В корне Git-репозитория должен присутствовать файл `README.md`, содержащий:

1. краткое описание проекта;
    
2. используемые технологии (Java, JavaFX, Maven / Eclipse и т.п.);
    
3. инструкцию:
    
    - по запуску JAR-версии;
        
    - по запуску EXE-версии;
        
4. (опционально) скриншоты GUI-приложения.
    

---

### 5. Критерии недопуска к защите

Проект **не допускается к защите**, если выполнено хотя бы одно из условий:

- отсутствует Git-репозиторий или история разработки формальная;
    
- проект загружен в репозиторий одним коммитом;
    
- JAR-файл не запускается;
    
- EXE-версия отсутствует или требует установленной JVM/JRE;
    
- отсутствует `README.md`.
    

---

### Методическая ремарка

> Цель данных требований — проверить не только корректность программы,  
> но и владение базовыми инженерными практиками:  
> поэтапная разработка, контроль версий, упаковка и доставка программного продукта.
